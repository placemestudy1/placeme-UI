# SPEC-0014 — Truthful product copy and room capacity

**Status:** Implemented — pending review
**Owner:** Shiva
**Reviewer:** Hruday
**Issue:** [SCRUM-23](https://placeme.atlassian.net/browse/SCRUM-23)
**Target release:** Sprint 1 candidate

## Problem

The candidate client contains claims that are stronger than the implemented
product behavior. It describes the evaluation as comparable to a real placement
panel, treats the largest talk-time share as leadership, claims room-code expiry
that the backend does not implement, and labels deterministic or generic
practice prompts as personalized. The desktop room form also accepts 2–5 seats
while its guidance recommends 6–8; the API contract supports 3–12.

The findings are recorded in `placeme-startup-playbook/01-repository-product-audit.md`
and the Sprint 1 acceptance criterion in SCRUM-23.

## Goals

- Remove the five known misleading claim classes from every supported route in
  the `place-me-UI` candidate.
- Align room-creation controls and guidance with the API's 3–12 participant
  contract.
- Add automated content QA that fails if the known claims return.

## Non Goals

- Validate the AI rubric against real placement panels.
- Add room-code expiry, a new recommendation engine, or new scoring behavior.
- Change the backend API, database schema, providers, or room lifecycle.
- Revive or modify the frozen legacy `gd-proto/apps/web` or Expo wrapper.

## Requirements

### Functional

- **R1:** Describe the score as generated by PlaceMe's current AI evaluation,
  without claiming equivalence to a real placement panel.
- **R2:** Describe talk-time rank neutrally; the highest share must not be called
  leading or leadership.
- **R3:** Explain that a code can join only a room that is still waiting, without
  claiming timed expiry.
- **R4:** Describe score-derived suggestions as based on the lowest sub-score,
  and generic suggestions as general practice topics; do not call either
  personalized.
- **R5:** Room-creation controls must accept only the API-supported 3–12 seat
  range. Capacity guidance must state that range and make no unsupported scoring
  threshold claim.
- **R6:** Apply the same truthful wording to desktop and `/app` routes where the
  affected concept appears.

### Security, privacy, and operations

- **R7:** Do not add tracking, storage, user data, dependencies, or network calls.
- **R8:** Rollout is a client-only copy/control change and must remain blocked
  from external release until the existing candidate release gates are met.

## Design

This is a client-only change. Existing API calls and response types remain
unchanged. Desktop room capacity changes from a 2–5 number input to 3–12 with a
default of 6. The `/app/new` selector exposes supported values from 3 through
12. Join filters retain their current behavior because they filter capacities
returned by the API and do not constrain creation.

Known text is replaced as follows:

| Current meaning | Truthful meaning |
|---|---|
| Real placement-panel weighting | PlaceMe AI evaluation rubric |
| Highest talk share means the user led | User had the highest tracked talk-time share |
| Code expires 15 minutes after end | Code joins only while the room is waiting |
| Generic/deterministic prompt is personalized | Score-based or general practice suggestion |
| 6–8 required for reliable AI scoring | Current room capacity is 3–12 |
